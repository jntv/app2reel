# Technical design

Last reviewed: 2026-10-27. Sources: `server/`, `shared/types.ts`, `src/`, `package.json`, README and user requirements. Architecture below describes implemented v0.1 behavior; extensions are proposed only.

## Components

REQ-001/003: React/Vite interface served by a loopback Express process. Zod validates requests. A per-project JSON file is atomically replaced through a serialized write queue; memory emits SSE state. There is no database migration, cloud hosting, or tenant model. Artifacts live under ignored `.capture/<uuid>/`.

REQ-002/005: `LocalAI` calls the installed Codex CLI with schema-constrained ephemeral read-only runs. It checks ChatGPT login, required safety flags, timeout and structured turn completion. It strips inherited API keys, shell tools, app integrations, MCP and skill discovery. Only the CLI handles credentials. Screenshot input and optional live web search are explicit.

REQ-004: Playwright uses separate unrecorded login contexts and isolated recorded exploration. Saved manual auth stays in memory for reuse across explorations and retries until its original expiry or explicit discard. Action IDs reference visible DOM controls. Allowed origins, dangerous-label checks, default method blocking, popup/download rejection and login detection bound actions. These are defense in depth, not a guarantee against hostile applications. Browser observations are untrusted model input.

REQ-009: `server/signin.ts` handles automatic account sign-in before recording. A run-specific authorization enables bounded reCAPTCHA checkbox/challenge attempts. Only a cropped challenge image, with inputs masked, goes to the Codex planner; no credentials or general page text do. Coordinate clicks must remain inside the current visible challenge bounds. Temporary screenshots and the unrecorded context are cleaned up on all exit paths. Fixed safe errors distinguish blocked, timed out, and failed authentication. No token injection, solver service or challenge bypass is used.

Manual fallback is managed by `server/login-sessions.ts`. It watches the unrecorded browser for verified sign-in and automatically captures cookies, localStorage, IndexedDB and origin-scoped sessionStorage, without waiting for a manual confirmation button. Automatic sign-in returns the same storage bundle; sessionStorage is restored before product scripts execute. Pending windows can remain open for four hours. Saved manual auth can be restored for multiple explorations and retries until eight hours after the original save; neither restoration nor duplicate confirmation extends that deadline. Supplying explicit exploration credentials, editing the brief, opening a new manual login, or shutting down discards the saved session. The UI polls a credential-free status endpoint, including after reload. This replaces the original 15-minute handoff that could discard a successful sign-in before the user confirmed it. Thirteen local-browser manager regressions cover autosave, duplicate confirmation, repeated storage restoration with fixed expiry, div-based sidebars, incomplete iframe MFA, public landing rejection, concurrent windows, origin boundaries and cleanup.

REQ-006/007/010: `render.ts` coordinates frame-driven H.264/AAC exports. `demo-renderer.ts` retimes genuine recording clips, applies a selective context/push/held-detail camera plan through FFmpeg, and composites transparent animated artwork from `demo-template.ts`. `demo-motion.ts` shares the exact camera projection between product pixels and cursor highlights. The window fills 95% of the frame width with rounded matte/shadow edges and a compact dark active-word subtitle panel; permanent editorial headers and lower thirds are removed. Small active ROIs permit up to2.2× cinematic close-ups; large overview regions remain restrained. Focus reveal is delayed until the incoming view settles. New recordings capture normalized pointer movement and trusted pointer-down events without input values. `cursor-detection.ts` observes the recording’s orange marker on the identical setpts/fps/tpad/trim output schedule used for footage and supplies one discrete position per rendered frame. This prevents interpolation drift between25fps source and30fps output. Trusted telemetry supplies click flags; it provides an approximate position fallback only when a new recording’s marker is absent. Legacy footage never acquires inferred clicks. A fractional-seek/native-PTS regression and fast-travel1×/1.12×/cloned-tail regression compare tracked points with actual decoded pixels. Reviewed scene focus/zoom and source-normalized focusArea outlines control framing. The camera ignores per-frame pointer movements; entry-travel is excluded from attention bounds during detail shots. Native clips run at most1.12× and short clips freeze their final frame instead of slowing the pointer. Boundary stills crossfade without shifting the narration clock. Disabling cursor effects removes both following and overlays. Cinematic/Subtle settings control movement strength.

`product-theme.ts` reads rendered CSS colors, typography, radii and measured dialog/main bounds during exploration. Safe models use a closed UI vocabulary and user feature words, excluding arbitrary customer/profile text. Captured public fonts use a hard2MB streaming limit, no cookies and validated font headers; `film-theme.ts` embeds them offline. Public design refresh uses an unrecorded read-only context; stored undimmed screenshot palettes recover signed-in styling without another login. `promo-template.ts` rebuilds deterministic dimensional interface cards, diagrams and kinetic type from these tokens/models. It does not display raw screen pixels or invent populated metrics in empty reporting views. Both renderers run in network-blocked Chromium, with untrusted strings rendered as text. Original pulse music is synthesized locally. Media/captions/voice assets are staged before publication; cancellation cleans temporary output while preserving previous films. Successful outputs carry a stable revision used by preview/download URLs and video keys; older projects fall back to their saved update timestamp. Versioned URLs refresh regenerated exports; the video requests inline playback, while the host browser controls native fullscreen behavior.

`narration.ts` defaults through render settings to local neural Indian-English MeloTTS ONNX speech, with optional Kokoro Heart/Michael US voices, preserving natural pauses and fitting at no more than1.12× tempo. The explicit System option retains macOS Samantha/eSpeak with silence trimming and a1.38× cap. Both normalize voice and export narration.wav/timing JSON, mixed above a quiet original music bed. Natural synthesis runs an isolated pinned Python bridge over JSON stdin/stdout; setup downloads verified official models once, while rendering is offline. No silent voice-provider fallback occurs. A per-project fingerprint of sanitized scene scripts, rounded scene durations and the voice choice permits reuse of validated PCM narration/timing during visual edits. A partial rerender that preserves a narrated film requires that exact shared voice cache; otherwise both films must be rendered so captions and audio remain consistent. `voice-alignment.ts` maps per-word pronunciations monotonically onto actual phoneme timestamps, including brands and expanded numbers. `subtitles.ts` groups short phrases; uncertain phoneme matches and system voices use weighted-word estimates within the spoken span. Indian English uses weighted word timing within its measured speech span because this export lacks word timestamps. Natural setup/status with per-voice readiness and bounded ephemeral WAV previews are exposed through narration-api.ts; preview text stays local and does not mutate projects. The same cues drive burned-in active-word subtitles and SRT/WebVTT exports. Promo headlines remain a separate animated design layer. Portrait and landscape promos use separate native compositions, selected by renderSettings.promoAspect; the demo stays landscape. The studio saves renderSettings, normalized per-scene focus points and privacy masks through PUT. `demo-privacy.ts` applies validated opaque source-pixel masks before camera transforms; invalid geometry fails rendering. The masks do not modify local raw media. Optional recordingRanges retain reviewed source intervals around waits. demo-edit.ts builds a temporary lossless FFV1 edit at the render frame rate and remaps telemetry; recording pixels, detected cursor and overlay share the edited clock, while source files and scene narration durations remain intact. Focus, mask and clip-only changes invalidate the demo while preserving the independent completed promo; story or movement/subtitle changes invalidate both. Optional fields keep older projects compatible.

Capture records Shot.entryStart/entrySettled/actionStart/actionEnd so selected footage includes actual UI interactions rather than AI waiting time. `shot-direction.ts` asks Codex to choose a readable real feature region from each selected screenshot, validates normalized bounds and camera strength, and falls back to measured DOM regions on inference failure. Cancellation propagates rather than silently falling back. These plans remain editable in Storyboard. REQ-008: Pipeline plans a coherent journey from incoming-action/current-result evidence, with outgoing intent explicitly distinguished. storyboard.ts sorts and deduplicates source indices, validates exact observed feature labels, allocates variable durations to an exact30fps budget with speech floors, and selects incoming actions plus a short settled-result hold. Narration over budget receives one bounded replan. It exports JSON/SRT/TXT and waits for review. It reserves a single global job before asynchronous persistence. Cancellable state reports through SSE and is recovered as interrupted after restart.

## Security, deployment, operations

`film-bookends.ts` computes deterministic intro/outro envelopes within the first/last reviewed scene clocks and supplies the shared full-screen branded artwork to both templates. `RenderSettings.bookends` defaults on, validates as an optional boolean for legacy projects, and saves through the existing style endpoint. An explicit inactive bookend state disables legacy internal brand beats when the toggle is off. Typography and the closing product URL use text-only DOM insertion; captions stay above the artwork. Browser PNGs can switch between RGB and RGBA as the intro becomes transparent; `demo-renderer.ts` decodes them locally into fixed-size RGBA frames before piping raw video to FFmpeg. This prevents filter-graph reinitialization from resetting source trims and advancing a held shot into a later page. Frame dimensions and byte count are checked, with the existing pipe backpressure bounding memory. No narration samples, source intervals, camera clocks or film durations are changed by the bookend treatment.

The original soundtrack is composed offline by `brand-music.ts` as deterministic 48 kHz stereo PCM: changing extended chords, warm keys/pads, soft bass, sparse plucks and a resolved ending. `audio-mix.ts` applies an independent low music gain, uses original mono speech as the sidechain key, and limits without automatic gain or lookahead delay. Both normal renders and `POST /music` use this mixer. Soundtrack-only updates validate original per-film voice caches, ignore previously mixed audio, and copy encoded video packets. They stage all replacements and retain rollback bytes until publication succeeds; voice, subtitle, timing, poster and previous export files remain untouched. New revisions invalidate cached player media.

Loopback host/origin validation and JSON-only mutations mitigate cross-site access; frame embedding is denied. No local multi-user auth exists, so do not expose the server on a public interface. Keep product test accounts disposable; recordings/screenshots can include PII. Credentials must never enter AI prompts/logs. Project URL query strings and link queries are excluded from model observations. Raw browser footage is published only after a successful exploration with no detected login form.

Run through Node22+, installed dependencies, current Codex CLI and Playwright Chromium. Configured environment values have no checked-in secrets. Logs are bounded project events, without raw CLI output. Stop the server to roll back code; remove ignored project directories for local data cleanup. Upgrade or re-explore rather than migrating old in-flight jobs. The source remote is `https://github.com/jntv/app2reel`; private `.capture` media and authentication state remain outside Git.

## Verification and limitations

Verification covers TypeScript/build, authentication/security regressions, real pointer capture, camera bounds and projection registration, legacy ring detection without fabricated clicks, deterministic screenshot-free graphics, shared subtitle timing, MP4 motion, cancellation and poster access. Live SmartSevak footage and local fixture recordings provide render inputs. Browser-login variants and arbitrary platforms are not comprehensively tested. See README for setup and limitations. Direct SIWC integration, richer role simulation, additional voice providers and generative media remain future adapters.

## Model-directed independent editing (2026-10-27)

`edit-plan.ts` supplies a schema-constrained editing language over a fixed reviewed source catalog. Codex selects source indices and context/detail framing, writes separate walkthrough/promo scripts, allocates variable scene durations, and authors camera hold/move/release seconds plus outgoing cut/dissolve/fade/slide transitions. Compilation preserves source intervals, privacy masks, observed labels and chronological walkthrough order; source reuse is explicit and never represented as a new recorded interaction. Speech budgets and exact30fps allocation remain enforced. One bounded correction attempt handles invalid drafts. No arbitrary media paths or mask-removal operations are available to the model.

For footage normalized by `prepareDemoEdit`, `clip-clock.ts` selects explicit exclusive source frame intervals before retiming. It supplies the same filter clock to footage and cursor analysis, caps the usable frames before cloning the tail, and avoids timestamp seeks into the millisecond-rounded Matroska timeline. This keeps held shots from acquiring a frame belonging to the following scene. Native recordings retain their original seek path.

Generated camera keys carry projected viewport endpoints and interpolate the full affine transform with quintic easing. This avoids pan-speed kinks caused by repeatedly clamping an interpolated camera center at the source edges. Footage, pointer and region projection consume the same transform. Authored releases on externally transitioned shots finish before the first transition handle, with an additional context settle. Dissolve opacity also uses quintic easing. `demo-artwork.ts` supplies deterministic multi-frame focus/identity envelopes and a label side chosen over the complete shot; wide context scenes do not flash a focus box immediately before a cut. Captions ease at phrase boundaries independently of active-word changes.

`retimePreparedNarration` accepts explicit reviewed old and new scene clocks. It validates the old fingerprint, voice recipe, complete PCM and cue bounds before copying the original take samples onto the new clock. Only zero padding is removed; nonzero samples, word order, gain, pitch and tempo are preserved. Captions move by the same sample offsets. Staging writes standard reusable WAV/timing files plus assembly/source-clock metadata; ordinary cache reads never infer an earlier clock or silently retime a mismatched track.

`POST /api/projects/:id/plan` re-edits existing captured material without browser activity. It commits new plans only after both compile; a failed/cancelled plan preserves completed films. `Project.editSources` is the reviewed source catalog; new masks on matching source intervals survive re-editing. `filmPlans.demo/promo` carry independent scene/narration clocks and per-kind media sidecars. Legacy scenes-only projects retain shared asset/cache compatibility. New projects target90s walkthrough/45s motion film, with20scenes/180s render caps; overlong inputs fail instead of truncating. Centered transitions use held boundary frames and preserve total narration time. Camera timing exposes a sustained context view, a smooth move, held detail and optional return to context. These operations refine available footage and do not fabricate missing product coverage.
